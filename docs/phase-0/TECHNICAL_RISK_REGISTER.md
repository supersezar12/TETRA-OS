# TETRA OS — Phase 0: Technical Risk Register
**Document ID:** `TETRA-P0-RISK-003`  
**Date:** 2026-11-21

| Risk ID | Category | Description | Likelihood | Impact | Mitigation Strategy |
|---|---|---|---|---|---|
| **R-01** | **Runtime / Solvers** | Python (`scipy`, `ortools`, `pulp`) and `pip` are absent in the container, risking failure if optimization relies on Python. | Certain (100%) | Critical | Standardize on Node.js + **`highs` (WASM MIT LP/MILP solver)** + verified TypeScript Convex/DP/Monte Carlo engines running in `node:worker_threads`. |
| **R-02** | **Database Persistence** | Local SQLite files in Cloud Run containers are ephemeral across container redeploys. | High | High | Use **Cloud SQL (PostgreSQL)** via platform integration as primary DB; support SQLite + exportable encrypted snapshot backup only as explicit local/dev fallback. |
| **R-03** | **Mathematical Integrity** | Returning `OPTIMAL` on a heuristic or timed-out run, or failing to detect `INFEASIBLE` constraints, misleads executive decisions. | Medium | Critical | Enforce strict Solver Status taxonomy (`OPTIMAL`, `FEASIBLE`, `INFEASIBLE`, `UNBOUNDED`, `TIME_LIMIT`, `INSUFFICIENT_DATA`, `AMBIGUOUS`, `FAILED`) and independent post-solve constraint feasibility verification. |
| **R-04** | **Data Quality / Hallucinated Metrics** | Computing Gross Profit without COGS, ROI without actual spend, or Price Elasticity with < N observations produces false commercial intelligence. | High | Critical | Enforce a mandatory **Data Sufficiency Gate** before every analytical, prediction, and optimization pipeline. Explicitly output missing fields and blocked metrics. |
| **R-05** | **AI Hallucination** | Generative AI (`@google/genai`) inventing KPIs, forecasts, or approving decisions instead of querying deterministic engines. | Medium | Critical | Implement strict **AI Orchestration Layer** using server-side tool/function calling bound to authenticated user/tenant context; AI may only explain verified engine JSON outputs and cannot mutate approvals or source data. |
| **R-06** | **Multi-Tenant Data Leakage** | A user in Company A accessing Company B's datasets, forecasts, or recommendations via API parameter tampering. | Medium | Critical | Enforce `company_id` + branch/region/department scope derivation from verified server session on every SQL query and API route; test cross-tenant denial in automated Security Tests. |
| **R-07** | **Event Loop Blocking** | Large MILP solves, Monte Carlo simulations, or Excel imports freezing the Express server for other users. | Medium | High | Offload heavy solves, backtesting, and bulk imports to `node:worker_threads` with DB-backed job queue, timeouts, and memory caps. |
| **R-08** | **Bilingual RTL/LTR & Currency Bugs** | Mixed Arabic/English layouts breaking charts, tables, or number formatting; mixing currencies across aggregations. | Medium | Medium | Use CSS logical properties (`ms-*`, `me-*`, `ps-*`, `text-start`), `dir` attribute switching, strict currency-unit tagging on every metric, and block un-converted multi-currency sums. |
| **R-09** | **Scope Creep / Shallow Implementation** | Attempting 19 deep enterprise modules simultaneously without finishing mathematical validation and E2E loops. | High | High | Execute strictly phase-by-phase with verifiable exit gates; build anchor optimization models deeply first, then expand remaining modules on the shared engine framework. |
| **R-10** | **File Upload Security** | Malicious CSV formula injection, oversized Excel bombs, or path traversal on file imports. | Medium | High | Enforce file size/row limits, MIME & magic-byte checks, in-memory/sandboxed parsing, CSV formula sanitization on export, and parameterized SQL queries. |
